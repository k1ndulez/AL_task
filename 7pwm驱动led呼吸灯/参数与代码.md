# 7 PWM 驱动 LED 呼吸灯

## 这一节要做什么

用定时器的 PWM 输出控制 LED 亮度，让 CCR 从 0 慢慢加到最大、再慢慢减回 0，灯就一呼一吸。
对应工程：`Documents\pwmhuxi`。

---

## 一、PWM 的三个量

```
PWM 频率 f = 定时器时钟 / ((PSC+1) × (ARR+1))
占空比      = CCR / (ARR+1)
```

- **ARR 决定分辨率**：ARR=99 时占空比只能按 1% 跳；ARR=999 时能按 0.1% 跳。
- **PSC 负责把 72 MHz 分频**，让频率落到想要的档位。
- **CCR 是你在运行中改的那个数**，它决定高电平占多少个计数。

顺序：先定 ARR（要多细）→ 再算 PSC（要多快）→ CCR 范围就是 0 ~ ARR。

---

## 二、CubeMX 配置

| 项目 | 设置 |
|---|---|
| TIM3 → Clock Source | Internal Clock |
| TIM3 → Channel1 | PWM Generation CH1 |
| Prescaler | `72 - 1` |
| Counter Period | `1000 - 1` |
| Pulse | `0` |
| 引脚 | PA6（TIM3_CH1），按你的板子丝印确认 |

验算：

```
f = 72,000,000 / (72 × 1000) = 1000 Hz
占空比 = CCR / 1000  →  0% ~ 100%
```

> 常说的“江科大原版参数”是 `PSC = 720-1`、`ARR = 100-1`，效果一样（1 kHz），
> 只是分辨率粗一些（1%）。两种都能用，代码里的循环上限要跟着改。

---

## 三、代码

### 1. 变量（`USER CODE BEGIN PV`）

```c
/* USER CODE BEGIN PV */
uint16_t PWM_Value = 0;
/* USER CODE END PV */
```

### 2. 启动 PWM（`USER CODE BEGIN 2`）

```c
  /* USER CODE BEGIN 2 */
  HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);   /* 让 TIM3_CH1 开始输出 */
  /* USER CODE END 2 */
```

### 3. 呼吸循环（`USER CODE BEGIN 3`）

```c
  while (1)
  {
    /* USER CODE END WHILE */

    /* USER CODE BEGIN 3 */
    /* 渐亮：CCR 0 → 1000 */
    while (PWM_Value < 1000)
    {
        PWM_Value++;
        __HAL_TIM_SetCompare(&htim3, TIM_CHANNEL_1, PWM_Value);
        HAL_Delay(1);
    }

    /* 渐暗：CCR 1000 → 0 */
    while (PWM_Value > 0)
    {
        PWM_Value--;
        __HAL_TIM_SetCompare(&htim3, TIM_CHANNEL_1, PWM_Value);
        HAL_Delay(1);
    }
    /* USER CODE END 3 */
  }
```

一个完整呼吸周期 = 1000 + 1000 步 × 1 ms = **2 秒**。

---

## 四、不同参数对应的循环上限

| PSC | ARR | 代码里的上限 | 频率 |
|---|---|---|---|
| `720-1` | `100-1` | `100` | 1 kHz |
| `72-1` | `1000-1` | `1000` | 1 kHz（推荐） |
| `72-1` | `5000-1` | `5000` | 200 Hz |

**CCR 一旦超过 ARR，PWM1 模式就恒为高电平**，看起来就是“一直最亮、不呼吸”。
所以改了 ARR 一定要同步改循环上限。

---

## 五、一个容易反的现象

如果占空比越大灯反而越暗，说明 LED 是**低电平点亮**。两种处理：

- CubeMX 里把 **CH Polarity** 设成 `Low`；
- 或代码里反过来写：

```c
__HAL_TIM_SetCompare(&htim3, TIM_CHANNEL_1, 1000 - PWM_Value);
```

---

## 六、这个写法的局限

两个 `while` 里都有 `HAL_Delay(1)`，CPU 被完全占住，做不了别的事。
如果板子上还要同时刷 OLED、读传感器，就不能这么写。

### 非阻塞版本（可选）

另外开一个 TIM6 做 5 ms 时基（PSC=72-1，ARR=5000-1），在中断里改 CCR：

```c
/* USER CODE BEGIN 0 */
uint8_t  dir = 1;
uint16_t pwm = 0;
/* USER CODE END 0 */

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
    if (htim->Instance != TIM6) return;

    if (dir) { if (++pwm >= 1000) dir = 0; }
    else     { if (pwm == 0)      dir = 1; else pwm--; }

    __HAL_TIM_SetCompare(&htim3, TIM_CHANNEL_1, pwm);
}
```

主循环里只需要 `HAL_TIM_Base_Start_IT(&htim6);`，CPU 就空出来了。

---

## 七、怎么验证

- 调试时在 WATCH 里加 `PWM_Value` 和 `htim3.Instance->CCR1`，能看到数值在 0–1000 之间往返；
- 万用表直流档量 PA6 对 GND，平均电压随呼吸在 0–3.3 V 之间来回变化；
- 用示波器能看到 1 kHz 方波，高电平宽度从 0 慢慢变到 1 ms。

---

## 八、踩过的坑

`pwmhuxi` 工程最初用的是 CubeMX 默认参数 **PSC=0、ARR=65535**，而代码只把 CCR 加到 500。
算下来占空比最大只有 `500 / 65536 ≈ 0.76%`，几乎看不出呼吸效果。
问题不在代码逻辑，而在 ARR 没改、CCR 上限又不匹配。
把 ARR 改成 `1000-1`、PSC 改成 `72-1`，循环上限改成 1000，就正常了。
